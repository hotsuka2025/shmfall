# shmfall

**shmfall** is a Python tool that reads time-series data in the WIN
format (Urabe, 1994) from the plain-text stream generated by `shmdump`,
and displays a real-time waterfall plot.\
In the current version, it **does not** access shared memory directly;
instead, it operates by piping the output of commands such as
`shmdump -tq` into `shmfall.py`.

This README provides a brief usage guide for `shmfall.py`.\
For a detailed description of the tool, see:

-   Otsuka, H., Tanaka, S., Shinohara, M., 2025. *Real-Time Waterfall
    Plot Tool for the WIN System*, Technical Research Report, Earthquake
    Research Institute, University of Tokyo, No. 31.

For an overview of the WIN system (Urabe & Tsukada, 1992), refer to:

-   **"What is the WIN system?"**\
    https://wwweic.eri.u-tokyo.ac.jp/WIN/

------------------------------------------------------------------------

## Overview

-   **Input:** Plain-text stream from `shmdump` (or equivalent data fed
    via stdin)\
-   **Output:** Real-time waterfall display (Matplotlib)
-   **Main components:**
    -   `StreamReader` --- stream ingestion & timestamp alignment
    -   `parse_data_stream` --- buffer management & rendering
-   **Default sampling rate:** `SAMPLING_RATE` (see source code; public
    version uses 100 Hz)
-   **Buffer length:** `MAX_SAMPLES = duration * SAMPLING_RATE`

## Basic Usage

Pipe the output of `shmdump` to `shmfall.py`:

``` sh
shmdump -tq <shm_id> -[L|H|B] <filter> -f <channel_table> -   | python3 shmfall.py -f <channel_table> [options]
```

------------------------------------------------------------------------

## Required Argument

-   **`-f, --channel_table`**\
    Channel definition file (e.g., `dastest_100ch.tbl`)

------------------------------------------------------------------------

## Main Options

-   **`-v, --vminmax`**\
    Color scale range `vmin:vmax`\
    Example: `-v -20000:20000`

-   **`-d, --duration`**\
    Display duration (sec).\
    Internally determines `MAX_SAMPLES = duration * SAMPLING_RATE`.

-   **`-n, --normalize`**\
    Normalization mode:

    -   `0` = Z-score
    -   `1` = Robust Z-score (median/MAD)

-   **`-e, --envelope`**\
    Signal processing:

    -   `0` = Envelope (Hilbert transform)
    -   `1` = RMS

-   **`-i, --ignore_zeros`**\
    Ignore channels whose traces are all zero (missing data).

-   **`-s, --sort_channels`**\
    Channel sorting:

    -   `0` = by longitude\
    -   `1` = by distance from a reference point

-   **`-r, --ref_point`**\
    Reference latitude/longitude used for distance sorting (`lat lon`)

-   **`--debug`**\
    Save the first rendered frame as `shmfall_latest_debug.png`.

-   **`--help`**\
    Show full argparse help.

## Usage Examples (from `example.sh`)

### 1. Continuous monitoring (shared memory ID 11)

``` sh
shmdump -tq 11 -H 2.0:1.0:0.5:5.0 -f dastest_100ch.ch -   | python3 shmfall.py -i -s0 -f dastest_100ch.ch -v-20000:20000 -d30
```

### 2. Envelope processing with debug frame output

``` sh
shmdump -tq 11 -H 2.0:1.0:0.5:5.0 -f dastest_100ch.ch -   | python3 shmfall.py -e0 -i -s0 -f dastest_100ch.ch -v0:30000 -d30 --debug
```

### 3. Offline use with a WIN-format file (via `shmdump`)

``` sh
cat sample_data/25051921.1925   | shmdump -tq -H 2.0:1.0:0.5:5.0 -f dastest_100ch.ch -   | python3 shmfall.py -i -s0 -f dastest_100ch.ch -v-20000:20000 -d30 --debug
```

## Debugging & Troubleshooting

-   `--debug` saves the first frame as `shmfall_latest_debug.png`
    (useful for checking visualization).
-   Ensure the channel table layout (ID, latitude, longitude, etc.)
    matches what `shmfall.py` expects;\
    the parser uses `split()` and fixed column indices.
-   For channel table specifications, see the WIN manual (Japanese):\
    https://wwweic.eri.u-tokyo.ac.jp/WIN/man.ja/win.html\
    ("2.2 Parameter file settings / \[2\] Channel table file")
-   If time alignment fails or gaps occur frequently, check the
    `shmdump` options and pipeline setup.

------------------------------------------------------------------------

## Notes

-   This tool depends on the exact text output format of `shmdump`.\
    If you provide a different format, update the parser in
    `shmfall.py`.
-   For large channel counts or high sampling rates, rendering load
    increases.\
    Adjust `-d` (duration) and sampling settings accordingly.
-   The channels used in the referenced publication are **not** included
    in this repository.\
    To test plotting only, you may create a simple channel table using
    arbitrary IDs (e.g., 0x0001--0x0064).
-   The sample data in this repository correspond to the 100-channel
    dataset used in the example figures.
